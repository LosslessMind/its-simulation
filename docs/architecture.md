# Архитектура проекта: ИТС — светофорное регулирование

Документ фиксирует техническое устройство текущей версии браузерной имитационной модели. Это справка по программной части проекта, а не готовый текст ВКР.

## 1. Назначение программы

Проект реализует браузерную имитационную модель регулируемого перекрёстка для сравнения режимов светофорного управления. Модель показывает движение автомобилей и пешеходов, работу фаз светофора, накопление очередей, ожидание и пропускную способность.

Программа работает локально в браузере без серверной части, сборки и внешних зависимостей. Публичная демонстрационная версия размещена на GitHub Pages: https://losslessmind.github.io/its-simulation/.

## 2. Стек

- HTML5.
- CSS3.
- JavaScript ES6.
- Canvas API.
- Без React, Vue, Angular и других фреймворков.
- Без npm, `package.json` и сборщика.

### `js/logger.js`

Реализует журнал событий.

Типы событий:

- `PHASE` — события фаз светофора;
- `AUTO` — прибытие и обслуживание автомобилей;

Возможности:

- очистка журнала;
- экспорт в TXT;
- ограничение количества записей в памяти и таблице.

### `js/intersection.js`

Содержит модель перекрёстка.

Основные сущности:

- `Car` — автомобиль;
- `Pedestrian` — пешеход;
- `Intersection` — состояние перекрёстка.

Модель хранит:

- 4 направления: `N`, `S`, `E`, `W`;
- 2 полосы на каждое направление: `left`, `right`;
- очереди автомобилей `queues[dir][lane]`;
- текущую ось фазы `currentAxis`;
- тип текущей фазы `currentPhaseType`;
- состояние светофора `green`, `yellow`, `red`, `off`;
- пешеходные сигналы;
- активных пешеходов;
- симуляционное время;
- статистику обслуживания и ожидания.

Распределение манёвров при создании автомобиля:

- 20% — левый поворот, полоса `left`;
- 50% — прямо, полоса `right`;
- 30% — правый поворот, полоса `right`.

Основные методы:

- `addCar(dir)` — создаёт автомобиль в направлении;
- `addPedestrian(crossing)` — создаёт пешехода у перехода;
- `serviceCars(axis, laneType)` — обслуживает автомобили на выбранной оси и полосе;
- `tick(dt)` — обновляет время ожидания, пешеходов и снимки очередей;
- `getDirQueueLen(dir)` — очередь по направлению;
- `getAxisLaneQueue(axis, lane)` — очередь по оси и полосе;
- `getTotalQueue()` — суммарная очередь;
- `getAvgWait()` — среднее ожидание обслуженных автомобилей;
- `getMaxWaitTime()` — максимальное текущее ожидание среди стоящих автомобилей;
- `getArrivalRate(dir, lane)` — оценка интенсивности прибытия для Webster;
- `reset()` — сброс модели.

### `js/traffic.js`

Отвечает за генерацию транспортного и пешеходного потока.

Класс: `TrafficGenerator`.

Автомобили генерируются по распределению Пуассона. Для каждого направления используется интенсивность `lambda` в автомобилях в секунду.

Ограничения:

- `QUEUE_CAP = 30` — максимум автомобилей в одном направлении;
- `PED_LAMBDA = 0.3` — интенсивность пешеходов на переход;
- `PED_CAP = 10` — максимум пешеходов на одном переходе.

Сценарии трафика:

| Ключ | Название | Особенности |
|---|---|---|
| `empty` | Пустая дорога | Все направления `λ = 0.15` |
| `morning` | Утро | Больше поток с юга и запада |
| `evening` | Вечер | Больше поток с севера и востока |
| `jam` | Пробка | Все направления `λ = 1.5` |
| `random` | Случайный трафик | `λ` меняется каждые 15–30 секунд |
| `rushhour` | Час пик | 5-минутный динамический сценарий |
| `daily` | Суточный | 10-минутный динамический сценарий |

Примечание: в пользовательских инструкциях сценарий может называться `rush_hour`, но в текущем коде используется ключ `rushhour`.

### `js/algorithm.js`

Содержит фазовый автомат и алгоритмы управления.

Классы:

- `PhaseRecord` — запись статистики одной фазы;
- `Algorithm` — логика выбора и выполнения фаз.

Текущий фазовый цикл:

```text
ns_main → ns_left → ew_main → ew_left
```

Фазы:

| Фаза | Ось | Полоса | Назначение |
|---|---|---|---|
| `ns_main` | `NS` | `right` | Север–юг: прямо + направо |
| `ns_left` | `NS` | `left` | Север–юг: левый поворот |
| `ew_main` | `EW` | `right` | Восток–запад: прямо + направо |
| `ew_left` | `EW` | `left` | Восток–запад: левый поворот |

Состояния автомата:

```text
idle → green → yellow → idle
```

Основные параметры:

| Параметр | Значение | Назначение |
|---|---:|---|
| `T_MIN` | 20 с | Минимум adaptive main-фазы |
| `T_MAX` | 55 с | Максимум adaptive main-фазы |
| `T_YELLOW` | 3 с | Жёлтый сигнал |
| `T_FIXED_MAIN` | 25 с | Fixed main-фаза |
| `T_FIXED_LEFT` | 10 с | Fixed left-фаза |
| `Q_MAX` | 60 | Нормирующая очередь |
| `SKIP_LEFT_MIN` | 3 | Порог пропуска left-фазы |
| `WAIT_FORCE_THRESHOLD` | 60 с | Порог принудительного выбора фазы |
| `WEBSTER_INTERVAL` | 30 с | Период пересчёта Webster |

### `js/app.js`

Точка входа приложения.

При `DOMContentLoaded` создаются экземпляры:

```js
logger       = new Logger();
intersection = new Intersection();
traffic      = new TrafficGenerator(intersection, logger);
stats        = new Stats();
algorithm    = new Algorithm(intersection, logger, stats);
ui           = new UI(intersection, algorithm);
```

Главный тик симуляции:

```text
traffic.tick(SIM_DT)
algorithm.tick(SIM_DT)
intersection.tick(SIM_DT)
_launchPendingExits()
ui.updateDOM(...)
stats.updateDOM(...)
```

`SIM_DT = 1.0`. Реальная частота тика зависит от ползунка скорости:

```text
interval = (SIM_DT / simSpeed) * 1000
```

Canvas-рендеринг работает отдельно через `requestAnimationFrame`.

## 5. Режимы работы

| Режим | Ключ | Поведение |
|---|---|---|
| Адаптивный | `adaptive` | Длительность зависит от очереди и ожидания |
| Фиксированный | `fixed` | Заданные длительности фаз |
| Webster | `webster` | Длительности рассчитываются по оценке интенсивности |
| Ручной | `manual` | Пользователь выбирает ось `NS` или `EW` |
| Ночной | `night` | Мигающий жёлтый сигнал |
| Пешеходный | `pedestrian` | Все пешеходные переходы зелёные, автомобили стоят |

## 6. Реализованные алгоритмы

### Adaptive

Адаптивный режим работает по 4-фазному циклу. Для main-фаз длительность рассчитывается по очереди на соответствующей оси и максимальному ожиданию:

```text
T = T_MIN + K × min(Q, Q_MAX) / Q_MAX × (T_MAX - T_MIN) + W_factor
W_factor = min(10, max_wait / 10)
```

Для left-фаз:

```text
T = max(5, min(15, 5 + Q_left × 1.5))
```

Особенности:

- left-фаза пропускается, если `Q_left < SKIP_LEFT_MIN`;
- пропущенные left-фазы считаются в статистике;
- если автомобиль ждёт больше `WAIT_FORCE_THRESHOLD = 60 с`, алгоритм может принудительно выбрать фазу для его направления и полосы;
- main-фаза может быть однократно продлена, если очередь превышает 70% от `Q_MAX`.

### Fixed

Фиксированный режим использует тот же 4-фазный автомат, но длительности не зависят от очередей:

```text
main-фаза: 25 с
left-фаза: 10 с
yellow: 3 с
```

### Webster

Режим Webster пересчитывает длительности фаз каждые 30 секунд. Используется оценка интенсивности прибытия по направлениям и полосам.

Формула:

```text
C = (1.5 × L + 5) / (1 - Yc)
Yc = sum(y_i)
y_i = max(λA, λB) / s
G_i = (C - L) × y_i / Yc
```

Параметры:

- `WEBSTER_L = 12`;
- `WEBSTER_S = 5.0`;
- минимум фазы `T_WEBSTER_MIN = 8`;
- максимум фазы `T_WEBSTER_MAX = 60`;
- если данных прибытия ещё нет, используется значение по умолчанию.

Для Webster также применяется пропуск left-фаз при малой очереди.

### Manual

В ручном режиме алгоритм ожидает команду пользователя:

- `btnNS` — ось север–юг;
- `btnEW` — ось восток–запад.

Ручной режим запускает только main-фазы выбранной оси.

### Night

В ночном режиме автомобильные светофоры мигают жёлтым с интервалом около 0.7 секунды. Пешеходные сигналы красные.

### Pedestrian

В пешеходном режиме на 20 секунд включается зелёный сигнал для всех пешеходных переходов. Автомобильные направления остаются без зелёной фазы.

## 7. Генерация трафика

Для автомобилей используется распределение Пуассона:

```text
k ~ Poisson(λ × dt)
```

В коде реализован классический алгоритм через произведение случайных чисел и порог `exp(-λ)`.

Для сценария `random` интенсивность по направлениям меняется каждые 15–30 секунд в диапазоне примерно `0.3–3.0`.

Для `rushhour` и `daily` интенсивность задаётся кусочно-линейно по времени симуляции:

- `rushhour` — 5-минутный цикл с переходом между спокойным периодом, утренним и вечерним пиком;
- `daily` — 10-минутный цикл с двумя пиками нагрузки.

Пешеходы генерируются накопительным счётчиком по каждому переходу.

- средняя длительность зелёной фазы;

## 12. Использованные данные тестирования

Сравнительное тестирование выполнено для 15 прогонов: 3 режима управления × 5 сценариев нагрузки. Проверялись режимы `adaptive`, `fixed` и `webster`; сценарии: `empty`, `morning`, `evening`, `jam` и `random`. Каждый прогон длился 300 секунд симуляционного времени.

Для каждого запуска фиксировались:

- режим;
- сценарий;
- длительность симуляции;
- среднее время ожидания;
- максимальное время ожидания;
- количество обслуженных автомобилей;
- итоговая очередь;
- пропускная способность;
- число завершённых фаз;
- число пропущенных left-фаз.

Средние результаты по пяти сценариям:

| Режим | Среднее ожидание, с | Среднее число обслуженных автомобилей | Средняя пропускная способность, авт/мин |
|---|---:|---:|---:|
| Адаптивный | 34,35 | 516,8 | 103,36 |
| Фиксированный | 37,45 | 467,8 | 93,56 |
| Вебстер | 47,29 | 346,6 | 69,32 |

Подробная таблица результатов и ограничения тестирования приведены в файле `docs/testing-plan.md`. Результаты относятся только к разработанной имитационной модели и не должны переноситься на реальные городские условия без дополнительной проверки.
